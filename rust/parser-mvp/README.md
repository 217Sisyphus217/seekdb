# 运行时 PEG 解析原型

验证语法作为数据、运行时解释执行的方案。CLI 使用独立 Cargo workspace；可显式启用下文的数据库接入实验。

```bash
cargo run --release --manifest-path rust/parser-mvp/Cargo.toml -- \
  'SELECT id, price * 2 AS total FROM orders WHERE id = 42'
```

输出 JSON 语法树。省略 SQL 参数时从标准输入读取；`--expr` 单独解析表达式。
重复解析同一输入可使用 `--repeat 10000`，输出初始化时间和每次解析耗时。

## 实现与范围

`src/sql.pest` 通过 `include_str!` 嵌入二进制。`Parser::new()` 调用
`pest_meta` 校验、优化语法，并创建 `pest_vm::Vm`。调用方创建一次 Parser 后复用；
`parse(&self, sql)` 使用独立匹配状态，成功后转换为持有自身字符串的 AST。
语法规则没有副作用，失败分支不修改最终 AST。没有 SQL 解析器代码生成步骤。

覆盖 SELECT、DISTINCT、别名、表连接、WHERE、GROUP BY、HAVING、ORDER BY、LIMIT、
子查询、函数调用，以及算术、逻辑、比较、IN、BETWEEN、LIKE、IS 运算。
表达式优先级通过分层规则表达；其余语法主要在 SELECT 和表引用规则中。

这是固定默认语义的 UTF-8 子集：支持 ASCII 未引用标识符、反引号标识符、单引号字符串、
有限的反斜杠转义和普通注释。关键词分类也仅覆盖该子集。
DDL/DML、PL、全文检索、UNION/CTE、完整 MySQL 方言、SQL mode、非 UTF-8 输入、hint、
版本注释、快速参数化和计划缓存均不在本轮范围内。AST 没有绑定表列或做类型检查。

`pest_vm` 用于快速验证运行时方案，不代表最终引擎选型；它也不是 DuckDB 的实现。

## 本机测量

Linux x86_64，Xeon Platinum 8369B，rustc 1.91.1；pest 系列固定 2.9.5。
Release 使用默认 opt-level=3、thin LTO、codegen-units=1，并保留调试信息。
时间均为 5 轮的中位数及范围，单线程解析；不同查询样例交替执行。

| 工作 | 中位数 | 范围 |
|---|---:|---:|
| 干净构建，包含依赖编译，`-j4` | 17.44 s | 16.75–17.95 s |
| 修改语法文本后的构建 | 8.38 s | 7.90–8.66 s |
| 初始化语法 | 21.77 ms | 21.15–22.59 ms |
| `SELECT 1` | 33.94 µs/次 | 33.39–34.63 µs |
| `SELECT id FROM users WHERE id=42` | 98.67 µs/次 | 95.29–109.19 µs |
| JOIN、分组、排序样例 | 529.55 µs/次 | 521.72–716.05 µs |

JOIN 样例：

```sql
SELECT u.id, count(o.id) AS n
FROM users u LEFT JOIN orders o ON u.id=o.uid
WHERE u.id BETWEEN 1 AND 100 AND o.id IS NOT NULL
GROUP BY u.id HAVING count(o.id)>2
ORDER BY n DESC LIMIT 20 OFFSET 5
```

解析计时包含匹配、AST 构造和销毁，排除语法初始化、JSON 序列化和进程启动。
每轮分别执行 20,000 / 10,000 / 2,000 次，全部成功。构建使用已下载依赖、离线模式和
不同的空 target 目录；OS 文件缓存未清除。语法修改测量追加注释，依赖编译产物保留；
仍需重编原型 crate 并链接。第一轮干净构建的开始阶段与独立 CPU 采样短暂重叠。

独立分配计数测得共享语法保留约 69.3 KiB；三个样例的额外堆峰值分别约
6.9 / 9.9 / 28.4 KiB，AST 销毁后净新增分配归零。这是 Rust 请求的堆字节数，
不包含栈、分配器元数据或原生代码的内部申请，不等同于进程 RSS。

独立 perf 采样中，约 26.9% 样本位于 VM 表达式解释、25.6% 位于 HashMap 查找、
10.6% 位于规则解释。没有使用采样运行的耗时作为上表数据。

验证包括 167 项检查（含与 Python 算术语法树对照）、4 线程共享语法生成 400 棵独立 AST、
100/500/2,000 个未闭合括号的错误输入，以及 `cargo clippy --release -- -D warnings`。
测试、分配计数器和测量脚本保留在仓库外，未提交。

结论：运行时语法与无副作用 AST 转换已跑通，外部 Bison/Flex 不是这个原型的构建依赖。
通用 VM 的规则解释和查表成本明显；进一步选型应评估初始化时解析规则引用、减少运行时查表的引擎。
当前只有语法子集，这些数字不能用来声称比现有完整 SQL 解析器更快。

## 旧解析器与生成版对照

同一台机器、相同 SQL，五轮交替运行。表格为中位数（最小–最大），单位 µs/次。

| SQL | 旧解析器 | pest_vm | pest_derive |
|---|---:|---:|---:|
| SELECT 1 | 0.90（0.87–1.84） | 34.49（33.93–46.13） | 12.52（12.08–13.08） |
| 简单点查 | 1.84（1.82–2.40） | 99.09（96.89–100.45） | 33.28（32.84–33.96） |
| 上述 JOIN 样例 | 7.71（7.61–9.42） | 584.83（532.93–730.50） | 187.33（177.62–220.18） |

旧侧调用实际 `ObParser::parse(..., STD_MODE)`，包括 AST 构造和生产使用的 arena 复用，
每次检查成功且输出为 SELECT；没有快速参数化、计划缓存或 SQL 执行。
旧解析器各编译单元用 Clang 重新按 O2 编译，其余链接库复用现有 O1 构建。
Rust 两侧使用相同 `.pest`、相同 AST 转换及 release 配置，计时包括 AST 销毁。
旧侧与 Rust 的 AST 布局、分配器不同；这些是当前实现的成本，不能推广为语言或 PEG 算法的性能排名。

生成版在仓库外使用 `pest_derive 2.9.5` 替换解释器，字符串规则名机械改成生成的 Rule 枚举，
167 项原有检查通过。独立采样显示生成版热点转为匹配状态恢复、忽略大小写的匹配、
注释规则和栈检查；不能仅靠消除解释器查表解决剩余差距。
生成版的三个样例额外堆峰值为 5,456 / 8,016 / 24,704 B，AST 销毁后净新增分配归零；
4 线程共享解析器生成 400 棵独立 AST 通过。这里仍是请求分配字节数，不是 RSS。
尚未对生成版做五轮构建时间对照。

结论：当前 `pest_vm` 适合继续验证接口，不适合直接替换生产解析器。
下一候选是能够直接构造 AST 的 `peg`；也需评估当前语法的重复匹配与中间树成本，
不能用本轮结果宣布某个 Rust 库最好。

## 数据库接入实验

默认构建不启用实验。准备好本机依赖后显式构建：

```bash
./build.py build -j16 --//rust:enable_parser_mvp=true seekdb
```

使用该二进制启动测试实例，在同一连接中执行：

```sql
SET ob_enable_plan_cache = false;
/*parser_mvp*/ SELECT 1 AS one, 42 AS answer;
```

如果使用 mysql CLI，需加 `--comments` 保留实验标记。标记必须位于语句开头。
实验只接管标准解析模式中带标记的语句；支持有可选别名的有符号 64 位范围内的
非负整数投影（如上例，以及括号包裹的整数），其他表达式和子句明确报错。
服务器仍在解析前拆分多语句请求，标记按语句生效。

Rust 通过现有 CXX 构建集成返回整数投影、别名、表达式原文和位置；
C++ 在查询的 arena 中创建现有 ParseNode，再交给原有 resolver 和 executor。
Rust 返回值在转换结束后释放，C++ 节点不借用 Rust 字符串。
这只是验证接口与内存所有权的最小切片，不是完整 AST 桥接设计。

接入时，pest 的栈检查在 seekdb 请求路径（含 SMART_CALL 栈切换）上
报告 `stack limit reached`。Rust 入口通过 `stacker::maybe_grow(256 KiB, 2 MiB, ...)`
在空间不足时建立库自身识别的栈，保留 pest 的栈保护。最终引擎选型需要考虑这项适配及成本。

Linux 实例验证通过 217 项检查，包括与旧路径比较值和列名、拒绝不支持的子句和非法 UTF-8、
错误后继续查询、4 个连接各 50 次独立解析。关闭计划缓存，通过同一 PyMySQL 连接交替测量
`SELECT 1 AS one, 42 AS answer`，每轮每条路径 1,000 次，五轮均成功：

| 路径 | 端到端中位数 | 范围 |
|---|---:|---:|
| 旧解析器 | 380.36 µs | 379.28–387.00 µs |
| PEG 实验入口 | 544.91 µs | 530.34–583.50 µs |

计时包含客户端、回环网络、解析、语义分析、执行、结果接收和正确性检查；
排除连接建立、首次语法初始化及预热。它不是解析耗时，也不代表含表查询的生产负载。
测试脚本、生成版对照源码、各轮原始数据和日志均保留在仓库外
`/data/1/nijia.nj/build-opt-results/peg-parser-mvp/`，没有提交测试。
